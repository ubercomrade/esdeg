# ESDEG — стабилизация и переход на Mimosa

## 1. Цель и принятые решения

Целевое состояние проекта:

- JASPAR и HOCOMOCO остаются источниками мотивов и их биологической аннотации.
- Представление мотивов, PCM→PFM→PWM, обработка `N`, обе цепи и сканирование выполняются через `mimosa-tool`.
- Первая рабочая версия поддерживает только мотивы из БД.
- Вторая версия добавляет файловые модели Mimosa без изменений статистического ядра.
- Новые PWM вычисляются по правилам Mimosa; численная идентичность старым результатам не требуется.
- GC-коррекция выполняется подбором фона по робастным квантилям; неработающий `--content` удаляется.
- `annotation` сохраняется, но переводится с отсутствующего `log2(OR)` на ROC AUC.
- Обратная совместимость сохраняется для основных входных файлов и enrichment-таблицы, но не для мёртвых и неработающих параметров.

## 2. Зависимости, упаковка и репозиторий

- Добавить `mimosa-tool>=1.4.6,<2.0`.
- Согласовать ограничения с Mimosa:
  - Python `>=3.12,<3.14`;

  - Numba `>=0.66`.
- Удалить `torch` и `scikit-learn`: после перехода на Mimosa они не используются.
- Оставить прямые зависимости NumPy и Numba, поскольку ESDEG использует их в статистическом коде.
- Добавить dev-группу с `pytest` и `ruff`; обновить `uv.lock`.
- Объявить package data:
  - `clusters/*.tsv`;
  - `hocomoco/*.jsonl`;
  - `logos/**/*.png`.
- Восстановить MIT `LICENSE`, заполнить минимальный README и добавить `.gitignore`.
- Удалить из Git:
  - `dist/`;
  - `*.egg-info`;
  - `__pycache__`/`*.pyc`;
  - сгенерированные XLSX/HTML и дублирующиеся example-результаты.
- Оставить только небольшие входные примеры и один воспроизводимый smoke-пример.

## 3. Единый контракт мотива

### 3.1. Внутреннее представление

Не вводить собственную иерархию моделей. Каждый мотив хранить как простой record/dict:

```python
{
    "model": mimosa.MotifModel,
    "motif_id": str,
    "tf_name": str,
    "tf_class": str,
    "tf_family": str,
}
```

Дополнительные поля, например `jaspar_cluster`, добавлять только в итоговую таблицу.

Сканирование и статистика должны использовать только `record["model"]` и не проверять конкретный класс (`PWM`, `BaMM`, `SiteGA` и т. п.). Это будет точкой расширения для второго этапа.

### 3.2. HOCOMOCO

- Читать bundled JSONL как сейчас.
- Явно проверять наличие обязательных полей и форму PCM `(4, length)`.
- Преобразовывать PCM исключительно средствами Mimosa:

```python
pfm = mimosa.pcm_to_pfm(pcm, pseudocount=0.25)
model = mimosa.pwm_from_pfm(pfm, background=0.25, name=motif_id)
```

- Удалить локальные `pcm_to_pfm`, `pfm_to_pwm` и ручное формирование N-строки.
- Сохранять текущие TF name/class/family; при отсутствии значения использовать строку `"NA"`.

### 3.3. JASPAR

- Оставить `pyjaspar` и зафиксированный release `JASPAR2024` для воспроизводимости.
- Явно извлекать PCM в порядке `A, C, G, T`, независимо от порядка ключей mapping.
- Создавать `mimosa.PWM` через те же `pcm_to_pfm` и `pwm_from_pfm`.
- Не выполнять глобальный `explode` и не размножать мономеры.
- В enrichment-таблице сохранять JASPAR-димеры как `TF1::TF2`.
- Неизвестную БД отклонять через `ValueError`, даже если CLI уже ограничивает choices.
- Сетевые ошибки JASPAR оборачивать сообщением с названием release и taxon; не продолжать с неполной БД.

## 4. FASTA и сканирование через Mimosa

- Читать FASTA через `mimosa.read_fasta`.
- Нормализовать ID промотора из имени FASTA по текущему документированному правилу: часть до первого `:`.
- Проверять:
  - FASTA не пуст;
  - ID не пустые и уникальные;
  - после сопоставления есть foreground и background;
  - каждая последовательность не короче максимального `mimosa.window_size(model)`.
- Не отбрасывать последовательности только из-за разной длины: Mimosa поддерживает ragged batches.
- Вычислять GC по закодированным последовательностям, считая коды C/G отдельно для каждой строки.
- Удалить `seq_to_int`, Torch convolution, `device`, `chunk_size` и группировку PWM по длине.
- Для каждого model выполнять:

```python
track = mimosa.scan(model, sequences, strands="best")
scores[:, motif_index] = np.maximum.reduceat(track.data, track.offsets[:-1])
```

- До `reduceat` гарантировать отсутствие пустых score-строк проверкой длины последовательностей.
- Результат сканирования оставить матрицей `float32 [n_sequences, n_motifs]`.
- Управление потоками сканера оставить стандартному `NUMBA_NUM_THREADS`; новый CLI-флаг для этого пока не добавлять.
- Добавить warm-up одного короткого scan перед измерением производительности, но не как обязательный пользовательский шаг.

## 5. GC-matched background

Заменить текущую реализацию, которая создаёт пустой фон на малых и дискретных выборках.

### 5.1. Валидация

- `foreground_gc` и `background_gc` должны быть непустыми конечными массивами в `[0, 1]`.
- `match_ratio` должен быть положительным целым числом.
- Целевой размер фона:

```text
min(len(background_pool), match_ratio * len(foreground))
```

- Никогда не дублировать один background promoter.

### 5.2. Разбиение и выборка

- Число квантилей: `max(1, min(10, n_foreground // 50))`.
- Получить границы по foreground, удалить повторяющиеся границы.
- Если все GC одинаковы, использовать один bin.
- Назначать bins через `searchsorted` по внутренним границам, чтобы максимум GC не выпадал из последнего bin.
- Распределять целевой размер фона по bins пропорционально числу foreground-наблюдений методом largest remainder.
- В каждом bin выбирать background без возвращения локальным `Generator`.
- Если bin не содержит достаточно элементов:
  - взять все доступные;
  - добрать дефицит из ещё не выбранных элементов соседних bins, начиная с ближайших по GC;
  - не создавать дубликаты.
- Логировать итоговый размер, средний GC foreground/background и число bins.

### 5.3. Публичный контракт

- Удалить `gc_threshold` из `esdeg()` и `--content` из CLI.
- Добавить `--match-ratio`, default `5`.
- Не называть последующую перестановку стратифицированной: документация должна говорить «permutation test on a GC-matched background».

## 6. Пермутации, AUC и воспроизводимость

- Заменить `np.trapz` на поддерживаемый Numba `np.trapezoid`.
- Добавить `cache=True` к численным `@njit`-функциям.
- Не менять сортировку ties: текущая агрегация одинаковых scores уже делает AUC независимым от их внутреннего порядка.
- Сохранить:
  - ROC AUC;
  - текущий prevalence-adjusted PR AUC;
  - upper-tail permutation p-values;
  - FDR для обоих наборов p-values.
- Явно документировать нестандартность PR AUC и односторонность теста.
- Добавить CLI/API-параметры:
  - `--n-permutations`, default `10000`;
  - `--seed`, default `0`;
  - существующий `--nproc`.
- Создавать независимые потоки через `numpy.random.SeedSequence(seed).spawn(1 + n_motifs)`:
  - один stream для GC matching;
  - отдельный seed для каждой модели.
- Устанавливать seed внутри `@njit permutation_loop`, а не через Python `np.random.seed`.
- Удалить неиспользуемые `foreground_gc`/`background_gc` из аргументов воркеров.
- Проверять `n_permutations >= 1` и `nproc >= 1`.
- При ошибке воркера прекращать анализ с сообщением, содержащим `motif_id`; не пропускать мотив молча.
- После FDR сортировать детерминированно: `auc_roc` по убыванию, затем `motif_id`.

## 7. Входные DEG/set данные

- Сделать общий reader табличных данных с `sep=None`, `engine="python"`, `comment="#"`, чтобы принимать CSV и TSV.
- Для DEG требовать `id`, `log2FoldChange`, `padj`.
- Проверять числовые колонки и понятным сообщением перечислять отсутствующие/нечисловые поля.
- Строки с NaN `padj` исключать из foreground и background, но сообщать их количество.
- Проверять допустимость `condition`.
- Для gene set:
  - игнорировать пустые строки;
  - дедуплицировать детерминированно;
  - отклонять пустой набор.
- До сканирования проверять:
  - пересечение foreground с FASTA не пусто;
  - background pool не пуст;
  - ID промоторов уникальны.
- Библиотечные функции должны бросать `ValueError`/`FileNotFoundError`, а не вызывать `sys.exit`.

## 8. JASPAR-димеры и metadata

- Enrichment должен содержать одну строку на motif ID.
- Значения `tf_name`, `tf_class`, `tf_family` хранить в исходной `::`-форме.
- Разворачивать димеры только в `annotation`:
  - split трёх metadata-полей по `::`;
  - определять целевое число элементов отдельно для каждой строки;
  - singleton class/family разрешается broadcast на два TF;
  - несовместимые длины больше одного считать ошибкой данных;
  - мономеры не дублировать.
- FDR рассчитывать до разворачивания димеров.

## 9. Annotation на основе AUC

### 9.1. Новый контракт

- Использовать `p_value_roc_adj` как motif-enrichment adjusted p-value.
- Сохранять исходное поле и добавлять alias `me_padj` в annotated output.
- Удалить `log2(or)`, `genes` и CLI `--log-odds`.
- Добавить `--min-auc`, default `0.5`.
- Фильтр motif enrichment:

```text
p_value_roc_adj < me_padj_threshold
and auc_roc >= min_auc
```

### 9.2. Expression annotation

- Парсить `gene_id` и `gene_name` из GTF независимо от порядка attributes.
- Валидировать DEG и counts schemas.
- Для нескольких gene IDs с одним TF name:
  - counts: использовать максимальное значение для проверки экспрессии;
  - DEG: выбирать запись с минимальным `padj`, при равенстве — с максимальным `abs(log2FoldChange)`.
- Для отсутствующих TF записывать NaN, а не нули.
- Expression-фильтр сохраняет TF, если выполняется хотя бы одно условие:
  - `de_padj < threshold` и `abs(lfc) >= threshold`;
  - `counts >= counts_threshold`.
- `--best` выбирает для каждого TF строку с минимальным `p_value_roc_adj`, затем максимальным `auc_roc`, затем минимальным `motif_id`.
- Итоговая таблица сохраняет все enrichment-колонки и добавляет:
  - `counts`;
  - `lfc`;
  - `de_padj`.
- Исправить TSV/XLSX writers так, чтобы они не выбрасывали эти поля.

## 10. Writers и CLI

- Использовать Python `None`, а не строку `"None"`, для optional output paths.
- Удалить дублирующиеся `write_table_ann` и `write_xlsx_ann`.
- Одна TSV-функция записывает переданный DataFrame без повторного жёсткого выбора несовместимых колонок.
- Одна XLSX-функция:
  - выбирает логотип по taxon либо ищет его по DB-каталогам;
  - пропускает отсутствующее изображение;
  - использует context manager;
  - не передаёт строку `"NA"` в `insert_image`.
- Исправить ширины колонок и reversed range.
- HTML report должен выбирать колонки по именам, не через `df.columns[:-1]`.
- Visualization:
  - Y = `auc_roc`;
  - корректный Y-range;
  - пустой significant subset создаёт понятное сообщение/пустой report, а не исключение;
  - p-values перед `log10` ограничиваются снизу положительным float;
  - threshold передаётся явно, default `0.05`.
- Все диагностические сообщения направлять в stderr через минимальную настройку `logging`; stdout не использовать для прогресса.
- CLI должен показывать фактические `seed`, `n_permutations`, `match_ratio`, число моделей и размеры выборок.

## 11. Поддержка других моделей Mimosa — второй этап

После стабилизации DB-пути добавить альтернативный источник моделей:

- Повторяемый аргумент `--model PATH`, взаимоисключающий с `--motifs`.
- Если не заданы ни `--model`, ни `--motifs`, использовать HOCOMOCO как текущий default.
- Каждый путь загружает ровно одну модель через:

```python
mimosa.read_model(path, format="auto")
```

- Поддерживаемые форматы определяются Mimosa: MEME/PFM, BaMM, SiteGA, Dimont, Slim и model bundle.
- Для пользовательской модели:
  - `motif_id = model.name`;
  - `tf_name`, `tf_class`, `tf_family` = `"NA"`;
  - cluster и logo отсутствуют;
  - enrichment работает полностью;
  - annotation пропускает такие строки из-за отсутствия TF metadata.
- Multi-motif MEME и metadata sidecar не включать в первый файловый релиз; пользователь предоставляет один model/bundle на путь.
- `ScoreProfile` не принимать как источник enrichment: это готовые score tracks, а не сканируемый `MotifModel`.
- Не добавлять registry/factory/plugin-слой: generic `MotifModel` в record уже является достаточной точкой расширения.

## 12. Тесты

### 12.1. Модели и БД

- HOCOMOCO PCM преобразуется теми же функциями Mimosa, что и ожидаемый эталон.
- JASPAR mapping с перемешанными ключами даёт порядок A/C/G/T.
- Все records содержат валидный `MotifModel`.
- Неизвестная БД даёт `ValueError`.
- Димеры не размножают enrichment-строки.

### 12.2. FASTA и scanning

- Forward/reverse-best scores совпадают с прямым вычислением на маленьком PWM.
- Ragged FASTA поддерживается.
- Повторяющиеся и пустые IDs отклоняются.
- Слишком короткая последовательность даёт раннюю понятную ошибку.
- Результат имеет форму `[n_sequences, n_models]` и конечные `float32`.

### 12.3. GC matching

- Foreground `<50` создаёт один рабочий bin.
- Одинаковый GC не создаёт пустой фон.
- Максимальное GC попадает в последний bin.
- В фоне нет повторяющихся индексов.
- Один seed возвращает один и тот же набор.
- Размер соответствует целевому либо размеру доступного pool.

### 12.4. Пермутации

- `compute_aucs` работает на NumPy 2.4.6.
- Идеальное и обратное ранжирование имеют ожидаемые ROC AUC.
- Ties дают стабильный результат.
- Один seed воспроизводит p-values между запусками.
- Разные модели получают разные RNG streams.
- Пустые группы и нулевое число permutations отклоняются.
- Минимальный p-value равен `1 / (n_permutations + 1)`.

### 12.5. Input и annotation

- Один DEG fixture читается и как CSV, и как TSV.
- Проверяется политика NaN `padj`.
- Пустой gene set отклоняется.
- Annotation принимает актуальную enrichment-схему.
- GTF attributes работают в разном порядке.
- Missing expression остаётся NaN.
- `--best` выбирает motif enrichment, а не DE p-value TF.
- Димер корректно превращается в две annotated строки.

### 12.6. Writers и packaging

- TSV сохраняет полный набор колонок.
- XLSX не падает без logo.
- Пустая visualization не падает.
- Wheel и sdist содержат HOCOMOCO, clusters и logos.
- CLI smoke проходит из установленного wheel, а не из repository root.
- Ruff проходит без ошибок.

### 12.7. Mimosa-интеграция

- Запускать тесты ESDEG вместе с зафиксированной поддерживаемой версией Mimosa.
- Добавить небольшой benchmark после JIT warm-up.
- На полном example фиксировать wall time и peak RSS.
- Численные результаты старой Torch-версии не считать golden reference; проверять инварианты, воспроизводимость и корректность ranking/p-values.
